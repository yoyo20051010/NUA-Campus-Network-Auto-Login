# 发版流程

这个项目有 Windows、macOS、OpenWrt 三个形态，发版时注意别让用户找错地方。

## 版本号怎么定

| 情况 | 发什么 |
| --- | --- |
| **两个平台都有改动** | 发 `vX.Y`（不带后缀），**Release 里同时挂 Windows 和 macOS 的包** —— 用户一个版本全搞定 |
| **只有 macOS 端改动**，不值得重新打包 Windows | 可以单独发 `vX.Y-macos` |

> 约定：主线版本由作者发；macOS 端的补丁版可以单独发 `-macos`。
> 但只要两边都有改动，就合并到同一个 `vX.Y` 里发。

## 打包

### Windows（标准版 / 含浏览器版）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\make_release.ps1
```

产物：`校园网自动登录_vX.Y_标准版.zip`（约 13MB，自带运行时）／
`..._含浏览器.zip`（约 50MB）

### macOS

```bash
python3 tools/make_release_macos.py
```

产物：`校园网自动登录_vX.Y_macOS版.zip`（约 50KB）

> ⚠️ 两个注意点：
> 1. **版本号取自 `macos/config.json` 里的 `version`**，发版前先改它，
>    并让它和 Release 的 tag 完全一致 —— 因为客户端的"自动检查更新"就是拿它比对的。
> 2. **必须用这个脚本打包**，不要用系统自带的 `zip` 命令：
>    后者压缩中文文件名时不写 UTF-8 标记（解压会乱码），
>    而且会把 `.command` / `.sh` 的可执行权限弄丢（双击就变成用文本编辑器打开了）。

### OpenWrt

把 `openwrt/` 目录打包即可。注意 `openwrt/campus_http.py` 需要和根目录那份保持同步。

## 发布

1. 发 `vX.Y` 时，把三个 zip 都挂到同一个 Release 下
2. Windows 的发版说明写在 `docs/releases/vX.Y.md`
3. macOS 的发版说明直接写在 Release 描述里（用户主要在 Release 页下载）
4. 发布后跑一次自检：
   - `python3 campus_http.py --check`
   - `python3 macos/campus_mac.py --status`（会顺带检查有没有新版本）
