# 发版流程

这个项目有 Windows、macOS、OpenWrt 三个形态，发版时注意别让用户找错地方。

## 版本号怎么定

| 情况 | 发什么 |
| --- | --- |
| **两个平台都有改动** | 发 `vX.Y`（不带后缀），**Release 里同时挂 Windows 和 macOS 的包** —— 用户一个版本全搞定 |
| **只有 macOS 端改动**，不值得重新打包 Windows | 可以单独发 `vX.Y-macos` |

> 约定：主线版本由作者发；macOS 端的补丁版可以单独发 `-macos`。
> 但只要两边都有改动，就合并到同一个 `vX.Y` 里发。

## 打包

### Windows（标准版 / 含浏览器版）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\make_release.ps1
```

产物：`校园网自动登录_vX.Y_标准版.zip`（约 13MB，自带运行时）／
`..._含浏览器组件.zip`（约 50MB）

挂 Release 时按下面的规则改名（**文件名里必须带 `windows`**，否则用户分不清
哪个包是给 Windows 的）：

| 本地产物 | Release 资产名 |
| --- | --- |
| `校园网自动登录_vX.Y_标准版.zip` | `NUA-Campus-Network-Auto-Login_vX.Y_windows_standard.zip` |
| `校园网自动登录_vX.Y_含浏览器组件.zip` | `NUA-Campus-Network-Auto-Login_vX.Y_windows_with-browser.zip` |

### macOS

```bash
python3 tools/make_release_macos.py
```

产物：`校园网自动登录_vX.Y_macOS版.zip`（约 50KB）

> ⚠️ 两个注意点：
> 1. **版本号取自 `macos/config.json` 里的 `version`**，发版前先改它，
>    并让它和 Release 的 tag 完全一致 —— 因为客户端的"自动检查更新"就是拿它比对的。
> 2. **必须用这个脚本打包**，不要用系统自带的 `zip` 命令：
>    后者压缩中文文件名时不写 UTF-8 标记（解压会乱码），
>    而且会把 `.command` / `.sh` 的可执行权限弄丢（双击就变成用文本编辑器打开了）。

### OpenWrt

把 `openwrt/` 目录打包即可。注意 `openwrt/campus_http.py` 需要和根目录那份保持同步。

```bash
python3 tools/make_release_openwrt.py
```

### OpenWrt C++ 版（可选，更省内存）

`openwrt-cpp/` 是同一套逻辑的 C++ 重写：静态二进制 421KB、常驻内存 0.5MB，
原来的 Python 版是 8MB 闪存 + 28~48MB 内存。包里的二进制是为
**aarch64** 编译的（小米 AX3000T / MT7981 这类机器就是）。

```powershell
pwsh -File openwrt-cpp/tools/build.ps1 -Test   # 先跑单元测试再交叉编译
python tools/make_release_openwrt_cpp.py        # 打包
```

产物 `NUA-Campus-Network-Auto-Login_vX.Y_openwrt-cpp-aarch64.zip`（约 210KB）。
和 Python 版的包**可以同时挂**：配置和账号文件两边通用，装哪个都能跑，
也可以随时换回来。文件名带 `aarch64` 是为了让用户一眼看出架构限制。

## 发布

> ⚠️ **Release 的资产名必须写纯英文。** GitHub 会把上传文件名里的非 ASCII 字符直接**删掉**，
> 不是变成乱码而是整段消失：`校园网自动登录_v1.3.1_macOS版.zip` 会变成 `_v1.3.1_macOS.zip`。
> `gh release create/upload` 和直接调上传 API 都一样（服务端行为，客户端改不了）。
> 所以挂 Release 时统一叫 `NUA-Campus-Network-Auto-Login_vX.Y_<平台>.zip`，
> **每个平台的包都要在文件名里写明平台**，不要出现不带平台的裸名
> （`_v1.4_standard.zip` 这种，用户会不知道是 Windows 还是别的系统）：
>
> | 平台 | Release 资产名 |
> | --- | --- |
> | Windows 标准版 | `NUA-Campus-Network-Auto-Login_vX.Y_windows_standard.zip` |
> | Windows 含浏览器 | `NUA-Campus-Network-Auto-Login_vX.Y_windows_with-browser.zip` |
> | macOS | `NUA-Campus-Network-Auto-Login_vX.Y_macos.zip` |
> | OpenWrt | `NUA-Campus-Network-Auto-Login_vX.Y_openwrt.zip` |
> | OpenWrt C++ | `NUA-Campus-Network-Auto-Login_vX.Y_openwrt-cpp-aarch64.zip` |
>
> zip **内部**的中文目录/文件名不受影响 —— Python 打包脚本已经写好 UTF-8 标记，解压正常。

1. 发 `vX.Y` 时，把各平台的 zip 都挂到同一个 Release 下
2. Windows 的发版说明写在 `docs/releases/vX.Y.md`，**必须写清支持的 Windows 版本**
   （当前为 **Windows 10 / 11 64 位**）以及每个包对应哪个平台 —— 用户经常拿 Win7
   或者更老的机器来问"能不能用"
3. macOS 的发版说明直接写在 Release 描述里（用户主要在 Release 页下载）
4. 发布后跑一次自检：
   - `python3 campus_http.py --check`
   - `python3 macos/campus_mac.py --status`（会顺带检查有没有新版本）
